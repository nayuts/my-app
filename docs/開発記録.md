## 2026-10-29：「平日＋洗濯」のようなパターンをどう作るか

**困ったこと・迷ったこと**
「＋洗濯」は独立したパターンにした。でも、そうすると「平日」と「平日＋洗濯」の両方に同じ家事が入るので、平日の家事が変わったときに、2つのパターンを両方直す必要がある。

**AIに聞いたこと**
どうするのがいいか聞いて、3つの案を比べてもらった。AIからはAをすすめられた。
- A：今のまま独立させる（「平日＋洗濯」を1つのパターンとして作る）
- B：組み合わせる（「平日」を選んだうえで「洗濯」を足して選ぶ）
- C：コピーして作る（「平日」をコピーし、洗濯を足して「平日＋洗濯」を作る）

**採用したこと**
A（独立させる）。
- 洗濯の日も、選ぶのは1つだけで済むので、4タップ以内の目標を守れる
- パターンは4つくらいの想定なので、家事が変わったときに直す手間は、毎日のタップ数に比べて小さい

**採用しなかったこと**
- B：洗濯の日は選ぶ操作が1回増え、4タップを超えるかもしれない。同じ家事が両方のパターンに入っていたときの回数の扱いなど、作るのも難しくなる
- C：新しいパターンを作るのは楽になるが、作った後に家事が変わったときに直す手間は、Aと変わらない

B と C は、パターンが増えて直すのが面倒になったら検討する（仕様のメモに記載）。

## 2026-10-29：ログインの方法をどうするか

**困ったこと・迷ったこと**
新規登録で何を入力すればいいか分からなかった。パスキーも気になったが、作るのが難しくなるのか分からなかった。

**AIに聞いたこと**
ログインに必要なもの（その人を見分けるもの、本人だと確かめるもの）と、方法ごとの比較を出してもらった。

| 方法 | 良いところ | 手放すもの |
| :--- | :--- | :--- |
| メールアドレス＋パスワード | カリキュラム（12章）で作ったことがあり、自分で直せる | パスワードの再設定にはメール送信が必要 |
| ユーザーID＋パスワード | メールアドレスが要らない | ほかの人と重ならない工夫が必要。再設定の手段が無い |
| パスキー | パスワードを打たない。安全 | 仕組み（WebAuthn）が新しく難しい。本番は HTTPS が必須で、教材の推奨構成（S3）だけでは足りない。予備のログイン方法も必要になりがち |
| Google などでログイン | パスワードを自分で管理しなくていい | 設定と仕組み（OAuth）が新しい。外部サービスの変更の影響を受ける |
| メールのリンクでログイン | パスワードが要らない | メール送信が必要。ログインのたびにメールを開くのでタップが増える |
| 認証サービス（Firebase、Cognito など） | パスキーなどもまとめて任せられる | 仕組みを自分で説明しにくい。外部サービスに頼る |

**わかった事実**
- 「一度ログインしたら、毎回ログインしなくていい」と決めたので、ログインはめったに無い。パスキーの「パスワードを打たなくていい」という良さは、このアプリではあまり活きない
- 通知はメールではなく、アプリの通知で受け取りたい。なので、メールアドレスを使う予定は、今のところパスワードの再設定くらい
- ログインの方法は「どう作るか」の話なので、②仕様ではなく④設計（ADR）で決めればよい

**採用したこと**
②仕様では「ニックネームを決めて新規登録できる」「一度ログインすれば毎回ログインしなくてよい」までを書き、ログインの方法は④設計で決める。

**採用しなかったこと**
今の時点でログインの方法を決めること。決めるための材料（上の比較）がそろったので、④設計で選ぶ。

## 2026-11-08：規模をどこまで削るか

**困ったこと・迷ったこと**
仕様と画面を詰めていくうちに機能が増え、自分で理解して説明できる範囲を超えそうだと感じた。がっつり削りたいが、削りすぎると既存アプリでいいかになる。

**AIに聞いたこと**
作るのが重いところや、カリキュラムで扱っていない新しい仕組みを簡単に挙げてもらい、削った場合に何を手放すかを比べてもらった。

**わかった事実**
- 説明が大変になるのは、機能の数より、カリキュラムで習っていない新しい仕組みのところ（グループ、パターンと家事のつなぎ方、まとめて登録・取り消し、朝5時の切り替え など）
- 「一段落では作らず、後で作る」にすれば、企画の困りごとは最終的に解決できる

**採用したこと（削った・後回しにしたもの）**
- 相手の画面への反映は、読み込み直したときにする
- 日付を選ぶのは後回し（今日だけ）
- ご褒美の使用履歴は後回し（今のアプリにも無いので、今より不便にはならない）
- 同じ名前の家事のチェックは後回し（二人なら名前の付け方で避けられる）
- 大変さでポイントを＋−する機能と、共同は後回し（企画の困りごとに直接つながらない）
- 家事の並べかえは後回し（指でつかんで動かす仕組みが新しい。一段落では名前の順）
- シートを下に引っぱって閉じるのは後回し（指の動きを読み取る仕組みが新しく、一覧のスクロールともぶつかる。一段落では×ボタン）
- アイコンは選ばずに、ニックネームの頭文字と決まった色にする

**採用しなかったこと（削らずに残したもの）**
- ポイントのバー：指でさっと決められるのが、使う人にとって大きい
- 完了画面、朝5時の切り替え、カテゴリのイラスト：二人にとって大事なので残す
- ログインの方法：ログインをやめると、ブラウザのデータが消えたときにアカウントに戻れなくなり、引き継ぎの仕組みを別に作ることになる。ユーザーIDかメールアドレス＋パスワードなら、スマホを変えてもログインするだけで引き継げるので、変えないほうが結果的に作るものが少ない

## 2026-11-08：グループをやめて、家で1つのアカウントにする

**困ったこと・迷ったこと**
今の形（一人ずつアカウントを作る → グループを作る → 合言葉で参加する）は、画面も仕組みも多い。もっと大きく削れないかと考えた。

**AIに聞いたこと**
大きく削れるところを聞き、Netflix のプロフィールのように、1つのアカウントに二人のプロフィールを作る形を提案された。これめちゃいいじゃんめちゃ軽くなりそうだ！

**比べたこと**

| 形 | 作るもの | 手放すもの |
| :--- | :--- | :--- |
| 一人ずつアカウント＋グループ（前の形） | アカウント登録、グループ作成・参加画面、合言葉、二人までの上限チェック、誰がどのグループにいるかを結びつける仕組み | ― |
| 家で1つのアカウント＋二人のプロフィール（新しい形） | 家のアカウントの登録、プロフィール選択画面（最初の一度だけ） | パスワードを二人で共有する。相手のプロフィールを選べば、相手として記録できてしまう |

**採用したこと**
家で1つのアカウント＋二人のプロフィールにした。選んだプロフィールはスマホに覚えさせるので、毎回選ぶ必要はない。グループ作成・参加画面、合言葉、上限のチェックとそのエラーが丸ごと無くなる。相手として記録できてしまう点は、「権限の制限はしない、二人の信頼関係に任せる」とすでに決めているので、同じ考え方で受け入れる。

**採用しなかったこと**
一人ずつアカウントを作ってグループで共有する形。三人以上や、家族で使うことも考えるなら向いているが、今回は同居している二人に絞ったので、そこまでの仕組みは要らない。
